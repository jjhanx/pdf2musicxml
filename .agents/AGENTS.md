# Coding Guidelines

- 수정이 발생할 때마다, 해당 수정사항이 특수한 엣지 케이스인지 일반적인 해결책(General Solution)인지 반드시 확인한다.
- 코드를 변경한 후에는 변경사항에 대한 내용을 프로젝트 문서(예: `docs/악보_변환_품질_가이드.md` 등 관련된 문서)에 항상 업데이트한다.
- 문서 업데이트까지 완료한 후에는 항상 Github에 `git push`하여 변경사항을 리포지토리에 반영한다.
- 사용자에게 이 규칙에 대해 여러 번 묻거나 반복해서 설명하도록 만들지 않고 자동으로 수행한다.
- **임시 파일 및 Git 커밋 주의사항**: 에러 분석이나 테스트를 위해 임시 스크립트(.py, .ts 등)나 테스트용 파일, 혹은 디버깅용 리포지토리(클론)를 생성할 경우, 프로젝트 작업 디렉토리를 오염시키지 않도록 반드시 시스템 스크래치 디렉토리(`<appDataDir>\brain\<conversation-id>\scratch\`)를 사용한다. 또한 Git 커밋 시 절대로 `git add .`를 무분별하게 사용하지 않으며, 항상 `git status`를 확인하거나 명시적으로 수정된 파일 경로만 `git add <file>` 형태로 추가하여 의도치 않은 파일이 리포지토리에 커밋되지 않도록 철저히 방지한다.
