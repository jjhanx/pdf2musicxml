# 가사 검토 데이터 복원 및 대용량 JSON 콜스택 초과 버그 수정

## 1. 문제점
- **대용량 백업 복원 시 콜스택 초과 크래시**: 2단계 가사 검토(HITL) 화면에서 대용량(수 MB, 수천~수만 단어)의 `review_backup.json`을 업로드하거나 로컬 스토리지에서 복원할 때, `merged.push(...missing)`와 같이 자바스크립트의 전개 연산자(`...spread`)를 사용하여 누락 항목을 한꺼번에 배열에 추가하면 함수 인자 수 제한을 초과하여 `RangeError: Maximum call stack size exceeded`가 발생하면서 가사 복원이 조용히 중단(크래시)되는 현상이 발생함.
- **빈 데이터 저장 및 1KB lyric_manifest.json 생성**: 복원이 실패하여 UI의 `reviewData`가 빈 상태인 채로 "완료 및 분리된 가사 저장"을 수행하면 서버에 빈 가사 목록이 전달되어 `ocr_data_pymupdf.json` 및 `lyric_manifest.json`이 1KB(빈 항목)로 생성됨.
- **3단계 진입 거부**: 3단계(`lyric_inject`) 실행 시 `lyricManifestHasItems` 유효성 검사에서 항목이 없어 "ZIP에 분리된 가사가 없습니다" 에러와 함께 파이프라인이 중단됨.
- **로컬 스토리지 복원 시 누락 항목 유실**: `handleLoadPrevious`에서 기존 `reviewData`가 비어있거나 일부만 있을 때 기존 항목만 map하고 누락 항목(missing)을 병합하지 않아 데이터가 유실되는 문제 존재.

## 2. 해결 내용
- **`src/App.tsx`**:
  - `handleUploadReview` 및 `handleLoadPrevious`에서 `push(...missing)` 방식 대신 메모리 및 인자 수 제한에 안전한 불변 배열 병합 메서드인 `merged.concat(missing)`을 사용하도록 수정.
  - `handleLoadPrevious`에도 `handleUploadReview`와 동일하게 `existingIds`를 기준으로 백업 데이터의 누락 항목(`missing`)을 찾아 안전하게 병합 및 좌표 정렬(`waveA - waveB || a.y - b.y || a.x - b.x`) 후 `reviewData`에 반영하도록 수정.

## 3. 일반적인 해결책(General Solution) 여부 확인
- **판정: 일반적인 해결책 (General Solution)**
- **이유**:
  1. 특정 악보 파일이나 특정 크기의 JSON에만 적용되는 엣지 케이스 처리가 아니라, 자바스크립트 V8 엔진의 함수 호출 스택 제한을 우회하는 표준적인 대용량 배열 병합 패턴(`Array.prototype.concat`)을 적용함.
  2. 파일 업로드(`handleUploadReview`)와 로컬 스토리지 불러오기(`handleLoadPrevious`) 양쪽 복원 경로 모두에 동일한 누락 항목 탐지 및 병합 로직을 일관되게 적용하여 데이터 완전성을 보장함.
  3. 모든 페이지 수, 모든 악보 크기(1KB ~ 수십 MB)에서 동일하게 동작하며 사이드 이펙트 없이 안정성을 보장함.

## 4. 하지 않는 일
- 임의로 악보 데이터의 항목을 필터링하거나 축소하여 전달하지 않음.
- 백업 파일의 정합성 검증 및 좌표 정렬 로직을 훼손하지 않음.
