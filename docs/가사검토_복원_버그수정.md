# 가사 검토 데이터 복원 및 lyric_manifest.json 1KB 생성 버그 수정

## 1. 문제점
- **가사 검토 UI에서 lyric_manifest.json 다운로드 시 1KB(빈 데이터) 저장**:
  - 2단계 OMR 후 가사 검토 UI(`reviewAfterOmr`)에서 `백업(.json) 저장`은 브라우저 React 상태(`reviewData`)를 5.6MB 크기로 정상 저장했으나, 바로 옆의 `lyric_manifest.json 저장` 버튼은 서버의 정적 파일 URL(`/api/lyric-manifest/:jobId/download`)로 연결되어 있었음.
  - 서버 디스크의 `lyric_manifest.json`은 OMR 실행 전(1단계 초기 자동 병합 시점)에 생성된 상태로 남아있거나 빈 상태(385바이트~1KB)였기 때문에, 사용자가 가사 검토를 완료하고 `lyric_manifest.json 저장`을 눌러도 1KB짜리 빈 매니페스트가 다운로드됨.
  - 이 1KB `lyric_manifest.json`을 3단계(`lyric_inject`)에 입력하면 "ZIP에 분리된 가사가 없습니다" 에러가 발생함.
- **`merge_lyric_sources.py`의 버전 키 의존성**:
  - `load_pymupdf_review`가 `data.get("v") in (2, 3)` 조건에 엄격하게 묶여 있어, `v` 필드가 없거나 다른 형식의 매니페스트 JSON을 로드할 때 항목을 빈 배열로 취급하는 문제.

## 2. 해결 내용
1. **`src/App.tsx`**:
   - `handleDownloadLyricManifest` 함수를 구현하여, 가사 검토 UI에서 `lyric_manifest.json 저장` 버튼 클릭 시 현재 검토 완료된 `reviewData`와 `manualLyricRects`를 포함하는 온전한 v3 `lyric_manifest.json`을 브라우저에서 즉시 생성하여 다운로드하도록 수정.
   - 기존 `<a href="/api/lyric-manifest/.../download">` 링크를 `<button onClick={handleDownloadLyricManifest}>`로 교체.
2. **`server/index.ts`**:
   - `GET /api/lyric-manifest/:jobId` 및 `GET /api/lyric-manifest/:jobId/download` API에서 세션에 `ocr_data_pymupdf.json`이 존재할 경우 `lyric_manifest.json`을 최신 검토 데이터로 자동 동기화한 뒤 전송하도록 백엔드 동기화 보강.
3. **`scripts/merge_lyric_sources.py`**:
   - `load_pymupdf_review`가 `v` 필드 유무와 관계없이 `items` 또는 `pymupdfReviewItems`가 존재하는 모든 딕셔너리 구조를 안전하게 읽도록 일반화.

## 3. 일반적인 해결책(General Solution) 여부 확인
- **판정: 일반적인 해결책 (General Solution)**
- **이유**:
  1. 클라이언트 UI 상태와 다운로드 기능 간의 불일치를 해소하여, 가사 검토 화면에서 작업한 모든 내용이 `review_backup.json`뿐만 아니라 `lyric_manifest.json`에도 100% 동일하게 반영되도록 구조를 개선함.
  2. 서버 및 Python 파이프라인의 JSON 로더를 유연하게 일반화하여 모든 버전/구조의 가사 매니페스트를 누락 없이 상호 호환 처리함.
  3. 특정 곡이나 특정 단계에 국한되지 않고 모든 악보 변환 파이프라인(1~3단계 전체)에 일관되게 적용됨.
